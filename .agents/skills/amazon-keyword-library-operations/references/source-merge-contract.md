# Three-source merge and first-board workbook contract

本合同由项目主任务使用，只负责把三个来源副任务的锁定回传做机械合并并装配第一板块十表；它不拥有来源提取、类目清洗或后续业务判断。

## Required handoffs

- SIF：七列关键词明细工作簿、核心词候选摘要、文件哈希、逐竞品原始响应指针、查询参数、最近30天口径、数据截止日、抓取时间、接口上限和异常状态。
- Amazon 联想：固定矩阵输入清单、可见建议、环境、执行次数、输入状态和证据指针。
- 卖家精灵：四列关键词工作簿、文件哈希、逐种子Pass/分页清单、原始响应指针、实际事件数/唯一词数、重复、冲突、缺失和损失状态。
- 主任务锁定：`Run_ID`、站点、产品事实、自有品牌、类目锚点、SKU事实、代表种子、三个来源版本和允许输出目录。

任一来源缺少工作簿哈希、版本、状态或原始证据清单指针时停止合并。主任务以`来源工作簿哈希 + Sheet行号`确定性生成`Handoff_Row_ID`，不要求把内部原始事件ID或逐行来源映射展开进四列/七列业务表。主任务只读取工作簿和紧凑清单，不读取原始长响应正文。Amazon 联想是必选来源；`not_executed`时可以装配问题发现型十表，但第一板块状态必须为不完整。

## Mechanical merge

机械键只允许：去首尾空格、压缩连续空格、英文小写化。不得做单复数归并、词干化、拼写纠正、词序重排、同义词合并、品牌删除、流量过滤或语义删除。

分页边界重复和内部原始事件只在对应来源副任务的本机事件清单中全部保留；主任务合并人口以锁定回传工作簿行作为边界。`07_关键词来源明细`每个`Handoff_Row_ID`一行，并指向来源工作簿、原始证据清单和聚合事件数；`08_原始关键词总表`每个机械键一行。同来源融合值冲突时，首次出现值只作展示，冲突状态和原始清单指针必须保留。

规范 ABA 和规范搜索量优先取卖家精灵；仅存在于 SIF 的关键词回退到 SIF。保留各来源原值、周期、规范来源和回退标记，不平均、不覆盖。Top3点击/转化只使用SIF。当前不再装配SPR、CPC、商品数量或集中度。

## Ten-sheet output

| Sheet | Required content |
|---|---|
| `00_执行概览` | Run、站点、产品、周期、三个来源版本与状态、行数、锚点、种子和阻断项 |
| `01_产品事实` | 分区保存类目锚点、自有品牌和 SKU 事实 |
| `02_竞品ASIN` | 获准竞品、父子体、SIF查询状态、周期和返回数 |
| `03_核心大词` | 主锚点、细分品类词、同义表达、代表种子和采用依据 |
| `04_SIF原始数据` | SIF副任务七列获准明细：竞品ASIN、返回序号、英文关键词、ABA排名、搜索量、Top3点击/转化份额 |
| `05_搜索框联想` | 联想副任务全部输入状态和可见建议 |
| `06_卖家精灵原始数据` | 卖家精灵副任务机械融合后的四列业务表：英文关键词、中文翻译、ABA月排名、月搜索量 |
| `07_关键词来源明细` | 每个回传工作簿行的一行统一索引：`Handoff_Row_ID`、来源工作簿/行、原始证据清单指针和聚合事件数 |
| `08_原始关键词总表` | 每个机械键一行，关联全部回传来源行、原始证据清单和规范字段 |
| `09_异常日志` | 失败、重试、零结果、总数漂移、重复、缺失字段和完成度影响 |

## Quality gate

1. 三个来源回传版本与主任务锁定版本一致。
2. 每条回传工作簿行有确定性`Handoff_Row_ID`，每个总表关键词至少连接一条来源明细，来源明细可回到锁定来源工作簿及其原始证据清单。
3. 回传工作簿行数与来源明细行数闭合；各副任务清单内部的原始事件数、聚合行数、重复/冲突和工作簿行数另行闭合，主任务不展开原始事件正文。
4. 没有发生语义删除、语义去重或流量分类。
5. 规范ABA/搜索量来源、SIF Top3、回退、周期和逐行缺失状态可识别；没有出现已移除字段。
6. 十张 Sheet 和必需列存在；公式错误为零，日期可读，长 ID/来源/周期/说明列可读并换行。
7. 每张 Sheet 已渲染；全部渲染和行数检查由独立质量验证 Skill 再次复核。
8. 任一必选来源未完成、显式适配器错误或联想`not_executed`时，第一板块完成状态必须为`incomplete/blocked`，不得交给清洗作为正式完成输入。
