# Amazon Keyword Library Operations

## 目标

维护项目当前基线、阶段状态、任务边界和验收记录，把 SIF、Amazon 联想、卖家精灵、清洗、词频、分类、竞争、趋势、最终工作簿、独立质量验证和发布工作路由给单一职责 Skill。SIF完成且主任务确认主锚点和代表种子后，Amazon联想与卖家精灵扩词并行；清洗闭环后，词频与关键词分类并行；分类完成后，竞争与趋势并行。三个来源均完成后由主任务按机械合同合并并装配第一板块十表，最终装配等待全部适用并行分支完成。来源副任务先在本地装配最小字段工作簿，只回传路径、哈希、行数和状态；主任务不接收逐页长响应。首轮真实正常案例虽已跑到最终工作簿，但 Amazon 联想仍为`not_executed`且2026-08-21减配后尚未重跑，因此状态是“正常案例进行中”，不得改成通过或边界案例。词频只路由到 V2.2 组件 draft Skill，且不改变 V2.1 清洗基线；竞争只用Top3两项绝对层且不再设样本门；趋势月份为空时不生成图。

## 输入

当前知识版本、用户确认决策、各单一职责任务回传、目标版本和验收要求；执行三来源合并时还需要三个来源的锁定工作簿/清单、类目锚点、SKU 事实和批次版本。

## 输出

版本目标、任务拆分、状态汇总、冲突清单、验收结论和可回滚的变更说明；需要合并来源时输出第一板块十表工作簿、来源映射和总门状态。

## 可调用能力

- `keyword.library.version.manage`
- `keyword.source.merge-and-assemble`

## 执行步骤

1. 完整读取 `knowledge/index.md`、`../../../docs/end-to-end-workflow.md`、`../../../docs/keyword-judgment-boundaries.md` 和执行当前任务需要的直接合同；三来源合并时必须读取 `references/source-merge-contract.md`。
2. 把 SIF 反查、Amazon 联想、卖家精灵扩词、清洗、词频、分类、竞争、趋势、最终工作簿、独立质量验证和发布分别路由到对应单一职责 draft Skill。词频只允许使用 Sheet2 和确认的机械统计合同；分类未确认边界由分类 Skill 停止或升级人工。
3. 为每个写任务定义一个目标、输入、排除项、风险、验收和回传格式。
4. 将工作路由到对应项目 Skill，不在本 Skill 内代做来源提取或业务判断。并行调度固定为三组：主锚点和种子确认后并行执行Amazon联想与卖家精灵扩词；清洗闭环后并行执行词频与关键词分类；分类完成后并行执行竞争与趋势。
5. 每组并行任务保留独立输入版本、输出状态和异常；下游汇合门必须等待全部适用分支回传，不能因一个分支完成而把另一分支默认为完成。长任务使用完成/需关注事件或长等待，不逐页轮询；副任务只在完成、阻断或需要单一决策时回传。词频不参与分类判断，但最终工作簿装配必须等待词频和第三板块两侧均完成。
6. 三个来源副任务均达到各自回传门后，使用 `keyword.source.merge-and-assemble` 从锁定工作簿和紧凑清单按机械键合并原始来源索引，生成十表工作簿并保留可回到本机原始响应的血缘；主任务不得把逐页/逐调用业务正文加载到对话。任一必选来源为`not_executed`或未完成时，十表只能标记不完整，不得进入第一板块正式完成状态。
7. 把装配后的阶段产物交给独立质量验证 Skill；汇总结果时区分已确认、候选、本地证据、排除项和待决策项。
8. 只有在证据、范围和状态一致时，更新版本记录和下一步。
9. 真实验证产生规则修正时，先写回拥有知识、边界和专责 Skill，再要求重跑当前案例并输出旧去向到新去向差异；旧工作簿只保留为旧规则证据。
10. 本次修改任何项目知识或 Skill 时，同批更新端到端说明的同步信息和受影响章节；没有流程影响时也明确记录已复核。
11. 只有用户明确授权且已形成稳定输入、来源、输出字段和停止门时，才允许建立 `draft` Skill；未确认阈值必须保留为`待确认`，不得用空壳能力冒充已执行或已验证。

## 质量标准

- 每个任务只有一个主要职责，状态和版本不互相覆盖。
- 并行分支具有明确的共同前置门和汇合门；任一适用分支未完成时，不提前启动依赖其结果的合并或最终装配。
- 三个来源各自保留独立完成状态；主任务合并不改变原始来源，不替代任何未完成来源；SIF和卖家精灵工作簿字段分别符合七列/四列最小合同。
- 知识事实、判定边界和执行流程分别由其拥有文件维护。
- 不把历史案例反向声明为新 Skill 的 P1 验证。
- 版本说明包含来源、适用范围、未完成项和回滚线索。
- 知识或 Skill 变更与端到端说明保持同批同步。

## 异常处理

出现所有权不清、规则冲突、公司政策不明、敏感内容或跨项目变更时停止并回传工作台总控。三个来源版本或主键无法对齐时停止合并并回传差异；业务判定不确定时按边界文档升级人工，不替代专责 Skill 作结论。
